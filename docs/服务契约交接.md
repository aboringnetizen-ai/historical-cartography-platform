# Phase 0 服务契约交接

共享契约使用 `@historical-cartography/shared-schema`。Schema v4.0 原字段在 [canonical.ts](../packages/shared-schema/src/canonical.ts)。新增的[服务读模型](../packages/shared-schema/src/service-contracts.ts)只描述服务边界，原数据契约指纹保持不变。

## 给 Gemini

用 [类型检查覆盖的地图样例](../packages/shared-schema/examples/service-examples.ts)搭建地图组件。输入为 `MapSnapshotRequest`，含明确的修订 ID 和历史 JDN。纪元区间为左闭右开。地图响应包含 `epoch`、`revision_id`、`data_status`、面和共享边界。面使用统一的 `control_score`，纯疆域与控制力切换可以使用同一个快照。外侧无限面用 `null` 表示。GeoJSON Polygon 是由拓扑派生的只读渲染数据。正式编辑提交通过空间操作接口。

样例为人工绘制的测试数据。前端清楚显示草稿状态，可用它验证请求、渲染和图层切换。正式地图快照、地名、政区和历史事件接口在空间与史料服务联通后扩展。具体传输方式在相应任务中和生产方确认。

`backend/core` 分支已有真实 PostGIS 草稿快照实现。可通过[拓扑包入口](../packages/topo-core/src/index.ts)和[本地运行说明](../packages/topo-core/README.md)接入。共享弧段可附带当前纪元的 `snapped_paleo_feature_id`。该可选字段属于服务读模型。

## 给后端 AI 2

实现面向 Codex 的 `EventEvidenceReader.verifyEvent`。请求可用 `event_revision` 固定证据核验版本。返回 `VERIFIED` 时提供实际事件、事件修订以及每条核验引文所属的文档与索引修订。返回 `PENDING_REVIEW` 或 `REJECTED` 时提供结构化门禁结果，并尽量定位到事件或引文。类型检查覆盖[待核验和引文失败样例](../packages/shared-schema/examples/service-examples.ts)。

`VERIFIED` 指服务已经核对引文。正式疆域提交仍由事务服务执行信源等级、事件关联、证据版本和人工审阅门禁。正例请用实际原文样本生成，让相关 Agent 可以复查页码、行号与内容。
